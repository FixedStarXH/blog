## 4. 具体问题清单(按严重程度)

### 🔴 高优先级(必须修)

| # | 位置 | 问题 | 建议 |
|---|------|------|------|
| P1 | `go.mod:5-52` | **全部依赖标记 `// indirect`**,包括直接使用的 gin/gorm/viper | 运行 `go mod tidy`,让直接依赖取消 indirect |
| P2 | `controller/category.go:22` | 字符串笔误 `"获取·列表失败"`(中文"·"混入) | 改为 `"获取分类列表失败"` |
| P3 | `model/init.go:59` | 测试密码哈希注释"明文 123456"与常用哈希不一致,**登录可能失败** | 用 `golang.org/x/crypto/bcrypt` 在代码里生成,或用正确哈希;写个登录验证测试 |
| P4 | 全项目 | **无任何测试** | 至少为 Service 层 + Model 行为方法写单元测试(见规范 §9) |
| P5 | `middleware/` | 空目录,无日志/恢复中间件(靠 gin.Default 默认) | 自定义 Logger/Recovery,统一日志格式(面试加分) |

### 🟡 中优先级(建议修)

| # | 位置 | 问题 | 建议 |
|---|------|------|------|
| P6 | `dao/` | 用 `db *gorm.DB` 全局传入,未抽象接口 | 重构为 `repository` 接口 + 实现(面试核心考点:依赖倒置) |
| P7 | `service/` | Service 同时依赖 DAO 与 `db *gorm.DB`,而 DAO 方法又要外部传 db,依赖传递冗余 | Service 依赖 Repository 接口(自带 db),不直接依赖裸 db;DAO 方法改为持有 db 而非每次传入 |
| P8 | `utils/response.go` | `Fail` 返回 HTTP 200 + code 400,语义混用 | 与文档约定一致即可,但要明确前端判断逻辑;`Error` 建议区分 500/404 |
| P9 | `router/router.go` | 手工 new 依赖,可读但规模小 | 数据量大后考虑 wire/手动 DI 容器(可选) |
| P10 | `README.md` 仍为"个人博客"描述 | 与 v2.0 多用户方向不一致 | 已更新为多用户 CMS 版（角色 / 审核流 / 三角色测试账号） |

## 5. 简历价值评估

### 5.1 现在的简历写法(不建议)

> "用 Go 实现了博客后端,有文章列表、详情、分类接口" — ❌ 太单薄

### 5.2 补齐后的简历写法(建议)

> **多用户博客系统 CMS（Go Web 全栈）** | 个人项目
> - 基于 **Go + Gin + GORM + MySQL** 从零搭建前后端分离内容平台，后端分层 **Controller/Service/Repository** 架构，通过接口注入依赖、支持 mock 测试
> - **多角色 RBAC**（普通/编辑/管理员）+ **JWT 鉴权** + **投稿审核工作流**（草稿→待审→发布/驳回），以及文章/分类/标签/评论 **CRUD**、**图片上传**、浏览量 **IP 防刷**、定时发布、私密文章等特性
> - 前端采用 **SPA + fetch**，瑞士国际主义视觉风格，响应式适配
> - 亮点：浏览量防刷（明细表+冗余计数+事务一致性）、标签多对多关联、评论审核状态机、软删除回收站、RSS/Sitemap、结构化日志
> - 工程化：单元测试、golangci-lint、Conventional Commits、README 文档

### 5.3 加分项(强烈建议加)

| 加分项 | 为什么 |
|--------|--------|
| **README 带架构图 + 截图** | 面试官 30 秒先看 README |
| **单测覆盖率** | 显示工程素养 |
| **部署体验**(Docker Compose / 一条命令起) | 显示可交付 |
| **提交历史规范**(Conventional Commits) | 显示团队协作习惯 |
| **演示链接 / 在线地址** | 一图胜千言(可部署到免费平台) |
