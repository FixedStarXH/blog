## 1. ER 关系总览

```
┌────────┐1───<┌────────────┐>───1┌──────────┐
│  User  │     │  Article   │     │ Category │
└────────┘     └─────┬──────┘     └──────────┘
    │                 │
    │1          ┌─────┼─────────────┐
    ▼           ▼     ▼             ▼
┌────────┐  ┌────────┐  ┌──────┐ ┌──────────┐
│ Column │  │Comment │  │ Tag  │ │ View/Like│
│(专栏)  │  └────────┘  └──────┘ └──────────┘
    │              │
    │1             │  (article_tags 多对多)
    └──< Article   │
         (专栏 1:N 文章)
```

| 关系 | 说明 |
|------|------|
| User 1:N Article | 多作者(`author_id`) |
| User 1:N Column | 一个作者可开多个专栏(`author_id`) |
| Column 1:N Article | 专栏下多篇文章(`column_id`,可空) |
| Category 1:N Article | 分类下多篇文章 |
| Article M:N Tag | 通过 `article_tags` |
| User 1:N Comment | 评论 |
| Article 1:N Comment | 文章下评论 |
| Comment 自引用 | `parent_id` 楼中楼 |
| User 1:N ArticleView/Like | 阅读记录、点赞记录 |

## 2. 表结构(完整)

> 通用:`gorm.Model` 提供 `id / created_at / updated_at / deleted_at`(软删除)。

### 2.1 users — 用户表(多角色)

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| username | varchar(50) | unique, not null | 用户名 |
| email | varchar(100) | unique, not null | 邮箱 |
| password | varchar(255) | not null | 密码(BCrypt) |
| nickname | varchar(50) | | 昵称 |
| avatar | varchar(255) | | 头像 URL |
| role | int | default 1, index | **角色:1 普通 2 编辑 3 管理员**(0=游客仅作概念,不落库) |
| status | int | default 1, index | **1 正常 0 禁用** |
| bio | varchar(255) | | 个人简介(作者页) |

**索引:** `role`(按角色筛选)、`status`(禁用管理)。

### 2.2 columns — 专栏表(系统特色)

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| name | varchar(100) | not null | 专栏名 |
| description | varchar(255) | | 专栏简介 |
| cover | varchar(255) | | 封面 |
| author_id | bigint unsigned | not null, index | 专栏作者 FK → users.id |
| status | int | default 1 | 1 正常 0 关闭 |

### 2.3 categories — 分类表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| name | varchar(50) | unique, not null | 分类名 |
| description | varchar(200) | | 描述 |
| sort | int | default 0 | 排序 |

### 2.4 tags — 标签表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| name | varchar(50) | unique, not null | 标签名 |

### 2.5 article_tags — 文章标签关联表

`(article_id, tag_id)` 联合主键,多对多。

### 2.6 articles — 文章表(含审核状态)

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| title | varchar(200) | not null, index | 标题 |
| content | longtext | not null | 正文(HTML) |
| summary | varchar(500) | | 摘要 |
| cover_image | varchar(255) | | 封面 |
| view_count | int | default 0 | 阅读量(冗余) |
| like_count | int | default 0 | 点赞数(冗余) |
| status | int | default 0, index | **0 草稿 1 已发布 2 待审核 3 已驳回** |
| reject_reason | varchar(255) | nullable | **驳回原因(状态=3 时)** |
| is_top | bool | default false, index | 置顶 |
| publish_at | datetime | | 发布时间(支持定时) |
| password | varchar(255) | nullable | 私密文章密码 |
| author_id | bigint unsigned | not null, index | 作者 FK |
| category_id | bigint unsigned | not null, index | 分类 FK |
| column_id | bigint unsigned | nullable, index | 专栏 FK(可空) |

**索引设计:**
- `(status, publish_at desc)` — 列表取已发布倒序
- `(author_id, status)` — 我的文章按状态
- `(status)` — 后台审核工作流筛选待审
- `(column_id)` — 专栏文章
- `(view_count)` — 热门排序

**状态机(投稿审核工作流):**

```
草稿(0) ──提交──▶ 待审核(2) ──通过──▶ 已发布(1)
   ▲                  │
   │                  └──驳回──▶ 已驳回(3) ──修改重提──▶ 待审核(2)
   └────────────────────────────────────────┘
```

### 2.7 comments — 评论表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| content | text | not null | 内容(纯文本) |
| status | int | default 0, index | 0 待审 1 通过 2 驳回 |
| article_id | bigint unsigned | not null, index | 文章 FK |
| user_id | bigint unsigned | nullable, index | 用户 FK(游客可空) |
| nickname | varchar(20) | nullable | 游客昵称 |
| parent_id | bigint unsigned | nullable, index | 父评论 |

**状态机(评论审核):**

```
待审(0) ──通过──▶ 通过(1)
   │
   └──驳回──▶ 驳回(2)
```

## 3. 设计关键决策

### 3.1 角色用 int 而非枚举表
- `role int`(1/2/3)简单高效,权限校验在中间件层做,适合中小系统。
- 若未来需要细粒度权限(如"只能审某专栏"),再引入 `permissions` 表。

### 3.2 文章状态机支撑审核工作流
- `status` 扩展为 4 态(0/1/2/3),覆盖"投稿→审核→发布/驳回"。
- `reject_reason` 记录驳回原因,作者重提前可查看。

### 3.3 定时发布的状态联动
- 设置定时发布(`publish_at` 为未来时间)时,文章初始状态为**草稿(0)**。
- 到点后由定时任务将其状态置为**已发布(1)**,同时 `publish_at` 写当前实际发布时间。
- 后台/作者在前台列表看到的是"草稿",到点自动转为可见。

### 3.4 软删除 + 冗余计数
- 前台资源软删除,支持回收站。
- `view_count / like_count` 冗余,配合明细表防刷。

### 3.5 专栏为作者个人空间
- `columns.author_id` 归属作者;文章 `column_id` 可空(非必属于专栏)。
- 专栏作为"作者主页"的进阶形态。

### 3.6 游客评论
- `comments.user_id` 可空 + `nickname` 冗余,降低参与门槛。
