# 博客系统(多用户 CMS)— 项目设计规范

> 本文档定义项目的工程规范,是代码评审与提交的"宪法"。
> 文档版本:v1.1
> 更新日期:2026-08-08

---

## 1. 分层架构规范

### 1.1 依赖方向(禁止倒置)

```
Controller → Service → Repository → DB
                 ↘
               Model(纯数据+行为)
```

**强制规则:**
- Controller 只做:解析请求、调用 Service、响应封装。**不含业务逻辑**。
- Service 只做:业务规则、事务、组装。**不直接操作数据库**,必须走 Repository 接口。
- Repository 只做:数据访问。**不写业务逻辑**。
- Model 只做:字段定义 + 状态判断方法。**不含 SQL、不含 HTTP**。
- 下层绝不能 import 上层(Service 不能 import Controller)。

### 1.2 依赖注入

- 所有依赖通过构造函数注入,禁止包级单例散落依赖。
- router 中统一组装:`repo → service → controller`。
- **禁止**在业务代码里 `model.DB` 全局变量直取(现 `service` 已注入 db,需统一)。

### 1.3 面向接口

- 每个 Repository 定义一个接口,如 `ArticleRepository`,GORM 实现 `ArticleRepo`。
- Service 依赖接口类型,便于 mock 测试与未来替换存储。

```go
// repository/article.go
type ArticleRepository interface {
    FindPublished(db *gorm.DB, page, pageSize int) ([]model.Article, int64, error)
    FindByID(db *gorm.DB, id uint) (*model.Article, error)
}
```

## 2. 命名规范

| 项 | 规则 | 示例 |
|----|------|------|
| 包名 | 小写单词,不用下划线/驼峰 | `controller` `service` |
| 接口名 | 动词能力 + er 结尾 | `ArticleRepository` |
| 实现名 | 接口名去 er 加 Repo / Impl | `ArticleRepo` |
| 构造函数 | `New + 类型名` | `NewArticleService` |
| 导出函数 | 大写开头,动词开头 | `GetArticleList` |
| 未导出函数 | 小写开头 | `getArticleByID` |
| 常量 | 大驼峰,语义化前缀(实体+状态) | `ArticleStatusDraft = 0` |
| 错误变量 | `Err` 前缀 | `ErrRecordNotFound` |
| 测试函数 | `Test + 被测函数名` | `TestGetArticleList` |
| 缩写 | 保持统一,不用混写 | 用 `ID` 不用 `Id`;用 `URL` 不用 `Url` |

**Model 字段用大驼峰**,JSON 序列化用 tag 指定小驼峰:`` `json:"viewCount"` ``。

## 3. 代码风格规范

### 3.1 强制工具

- `gofmt` — 提交前必须运行(IDE 保存时自动)。
- `go vet ./...` — 提交前必须无 error。
- `golangci-lint` — 建议启用(如时间允许),重点:errcheck、staticcheck、govet。
- `go mod tidy` — 依赖变更后运行,保持 go.mod 干净。

### 3.2 注释规范

- **导出标识符必须有注释**,以标识符名开头:`// Article 表示博客文章。`
- 业务关键逻辑写"为什么",不写"是什么"。
- 中文注释为主,与现有代码一致。

### 3.3 错误处理

- **不要吞错**:每个 err 必须处理或显式 `_ =`。禁止 `err := ...` 后不管。
- **向上抛错带上下文**:用 `fmt.Errorf("获取文章失败: %w", err)` 包一层,保留 `%w`。
- **Service 层返回领域错误**,Controller 层翻译成用户 message。
- 定义可复用错误:`var ErrNotFound = errors.New("记录不存在")`。

## 4. 日志规范

| 场景 | 级别 | 内容 |
|------|------|------|
| 请求日志 | Info | 方法、路径、状态码、耗时、IP |
| 业务操作(登录/发布) | Info | 谁在何时做了什么 |
| 参数校验失败 | Warn | 路径 + 错误原因 |
| 数据库错误 | Error | 完整堆栈 + 关联 ID |
| 未捕获 panic | Error | Recovery 中间件记录 |

- 使用 `log/slog`(Go 1.21+)结构化日志,生产输出 JSON。
- 日志不打印密码、token 等敏感信息。

## 5. API 规范

- 统一 `{code, message, data}` 响应(见接口设计文档)。
- 列表接口统一 `{list, total, page, pageSize}`。
- 参数校验在 Controller 层用 `validator` 或手写,失败返回 `code 400 + 具体 message`。
- 所有时间字段 ISO8601 字符串输出,前端统一格式化。
- 公共接口幂等/安全:GET 只读,写操作显式 POST/PUT/DELETE。
- 鉴权:**JWT 双 token**(access 2h 业务鉴权 + refresh 7d 换新),请求头统一 `Authorization: Bearer <accessToken>`,中间件校验类型与角色。
- 登出/刷新:refresh 用 Redis 白名单(`token:refresh:{jti}`)做轮换吊销;登录/刷新接口限流。

## 6. 数据库规范

### 6.1 模型

- 所有业务表继承 `gorm.Model`(含软删除),字段用 tag 注明约束与 comment:
  `gorm:"not null;size:50;comment:分类名称"`
- 时间字段用 `time.Time`;状态字段用 int 常量,不裸数字。
- 角色/状态常量统一放 `model/const.go`,一处定义处处引用:

```go
// 角色(游客 0 仅作概念,不落库)
const (
    RoleGuest  = 0
    RoleUser   = 1
    RoleEditor = 2
    RoleAdmin  = 3
)

// 文章状态(投稿审核工作流)
const (
    ArticleStatusDraft     = 0 // 草稿
    ArticleStatusPublished = 1 // 已发布
    ArticleStatusPending   = 2 // 待审核
    ArticleStatusRejected  = 3 // 已驳回
)

// 评论状态
const (
    CommentStatusPending  = 0 // 待审
    CommentStatusApproved = 1 // 通过
    CommentStatusRejected = 2 // 驳回
)
```

### 6.2 迁移

- 用 GORM `AutoMigrate` 管理,新表在 `model/init.go` 登记。
- **禁止**直接手写 DDL 进仓库;迁移脚本走 AutoMigrate 或 migration 目录。

### 6.3 查询

- 禁止字符串拼接 SQL,全部走 GORM 参数化查询。
- 列表查询必须分页,`pageSize` 上限 50。
- 热点列表(首页头条、热门)加索引支持。
- 列表接口**不返回**长文本字段(Content),减少传输。

### 6.4 写入

- 多表写入用事务:`db.Transaction(func(tx *gorm.DB) error { ... })`。
- 冗余计数(如 view_count)必须与明细表在同一事务内更新。

## 7. 安全规范

| 项 | 要求 |
|----|------|
| 密码 | 一律 BCrypt 哈希存储,禁止明文 |
| JWT | **双 token**:access 2 小时业务用、refresh 7 天换新;载荷带 `token_type` 隔离类型,refresh 用 `jti` + Redis 白名单做轮换吊销;Secret 从配置读取,生产用环境变量注入 |
| SQL | 全参数化,杜绝注入 |
| XSS | 评论等用户输入存纯文本,渲染前转义 |
| 上传 | 白名单扩展名 jpg/png/gif/webp;大小 ≤ 5MB;重命名防路径穿越 |
| 敏感配置 | `config.yaml` 加入 .gitignore,不提交数据库密码/JWT Secret |
| 越权 | 后台接口校验 role>=2(编辑及以上),中间件统一拦截;用户管理等敏感操作 role=3 |
| 速率 | 登录/刷新等接口限流(中间件),防暴力破解与 token 遍历 |

## 8. Git 工作流规范

### 8.1 分支策略

```
main         稳定可发布分支(保护)
  └── feat/xxx   功能分支(命名:feat/文章管理)
  └── fix/xxx    修复分支(命名:fix/评论审核)
```

- 小步提交,一个功能一个 commit。
- 合并用 `--no-ff` 保留分支历史。

### 8.2 Commit Message 规范(Conventional Commits)

```
<type>(<scope>): <subject>

feat(article): 新增文章 CRUD 接口
fix(comment): 修复审核状态更新未生效
refactor(repo): dao 重构为 repository 接口
docs: 补充接口设计文档
```

| type | 含义 |
|------|------|
| feat | 新功能 |
| fix | 修复 |
| docs | 文档 |
| style | 格式(不影响逻辑) |
| refactor | 重构(不改变行为) |
| test | 测试 |
| chore | 构建/工具/依赖 |

### 8.3 提交前检查清单

- [ ] `gofmt` / `go vet` 通过
- [ ] 无未处理的错误
- [ ] 依赖已 `go mod tidy`
- [ ] 敏感信息未入库
- [ ] 提交信息符合规范

## 9. 测试规范

- 核心 Service 层写单元测试(接口注入,便于 mock)。
- Repository 层可写数据库集成测试(可选)。
- 测试文件与被测文件同目录:`article_service_test.go`。
- 表驱动测试(Table-Driven Tests)为标准写法:

```go
func TestIsPublished(t *testing.T) {
    cases := []struct{ name string; status int; want bool }{
        {"已发布", 1, true},
        {"草稿", 0, false},
    }
    for _, c := range cases {
        t.Run(c.name, func(t *testing.T) {
            a := model.Article{Status: c.status}
            if got := a.IsPublished(); got != c.want {
                t.Errorf("IsPublished() = %v, want %v", got, c.want)
            }
        })
    }
}
```

## 10. 依赖管理规范

- 使用 Go Modules(`go mod init`),Go 版本在 go.mod 声明。
- **直接依赖不允许标记 `indirect`**——如出现,运行 `go mod tidy` 修正。
- 引入新依赖需评估:是否值得、是否活跃维护、许可证。
- 升级依赖走小步,并跑全部测试。

---

## 11. 配置管理规范

- 配置统一 YAML,`config/config.go` 读取,结构体映射。
- **环境变量覆盖已实现**:`viper.AutomaticEnv()` + 前缀 `BLOG_`,路径点号转下划线 —— `BLOG_MYSQL_HOST` → `mysql.host`、`BLOG_JWT_SECRET` → `jwt.secret` 等。
- 本地开发读 `config.yaml`(不入库);容器/生产只靠默认值 + 环境变量,`config.yaml` 缺失不报错。
- 敏感字段(JWT Secret、DB 密码)生产用环境变量,不入库。
