## 0. 开发原则

1. **小步提交**:一个阶段一个里程碑,每阶段完成后**编译 + 接口自测通过**再进入下一阶段。
2. **契约驱动**:先看接口文档定好的请求/响应,再写代码,前端已按契约就绪。
3. **分层规范**:Controller 只做参数校验与响应;Service 做业务;Repository 做数据(详见项目设计规范)。
4. **面向对象**:Repository 接口 + Model 行为方法。
5. **可验证**:每个阶段附 curl 测试命令,能用命令行跑通才算完成。

## 阶段三:用户体系

### 目标
注册/登录/我的资料接口可用,前端 login/register 页跑通。

### 任务清单

| # | 任务 | 接口 |
|---|------|------|
| 3.1 | 注册(用户名/邮箱唯一校验) | `POST /api/auth/register` |
| 3.2 | 登录(用户名或邮箱 + 密码) | `POST /api/auth/login` |
| 3.3 | 当前用户 | `GET /api/auth/me` |
| 3.4 | 更新资料 | `PUT /api/auth/me` |
| 3.5 | 修改密码 | `PUT /api/auth/password` |

### 验证

```bash
# 注册
curl -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"lumi","email":"lumi@ex.com","password":"123456"}'
# → 返回 token + user

# 登录
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"lumi","password":"123456"}'

# 我的信息(带 token)
curl http://localhost:8080/api/auth/me -H "Authorization: Bearer <token>"
```

### 完成标准
- 注册→登录→me 全链路 curl 通过
- 重复注册返回 code 400 "用户名已存在"
- 错误密码返回 code 400

| 4.6 | 权限:只能操作自己的文章(越权返回 403) | — |

### 验证

```bash
# 投稿
curl -X POST http://localhost:8080/api/my/articles \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"title":"我的第一篇文章","content":"<p>正文</p>","categoryId":1,"summary":"摘要","tagIds":[1]}'
# → 返回文章,status=2

# 我的文章
curl http://localhost:8080/api/my/articles -H "Authorization: Bearer <token>"
```

### 完成标准
- 投稿后 status=2,前台 `/api/articles` 不显示(未发布)
- 越权改他人文章返回 403

## 阶段六:后台管理

### 目标
管理控制台全功能:文章审核工作流 + 用户管理 + 分类/标签/专栏 + 评论管理。

### 任务清单

| # | 任务 | 接口 |
|---|------|------|
| 6.1 | 后台登录(role>=2) | `POST /api/admin/login` |
| 6.2 | 仪表盘统计 | `GET /api/admin/dashboard` |
| 6.3 | 文章审核工作流 | `GET /api/admin/articles` `PUT .../approve` `PUT .../reject` |
| 6.4 | 后台文章管理 CRUD | `GET/POST/PUT/DELETE /api/admin/articles[...]` |
| 6.5 | 置顶 | `PUT /api/admin/articles/:id/top` |
| 6.6 | 用户管理(role=3) | `GET /api/admin/users` `PUT .../role` `PUT .../status` |
| 6.7 | 分类/标签/专栏管理 | `/api/admin/categories|tags|columns` CRUD |
| 6.8 | 评论审核 | `GET/PUT/DELETE /api/admin/comments[...]` + `batch` |
| 6.9 | 图片上传/图库 | `POST /api/admin/upload` `GET/DELETE /api/admin/images` |
| 6.10 | 站点设置/友链 | `GET/PUT /api/admin/settings` `GET/POST/PUT/DELETE /api/admin/links` |

### 验证

```bash
# 编辑登录后台
curl -X POST http://localhost:8080/api/admin/login -d '{"username":"editor","password":"123456"}'

# 待审列表
curl "http://localhost:8080/api/admin/articles?status=2" -H "Authorization: Bearer <editor_token>"

# 审核通过
curl -X PUT "http://localhost:8080/api/admin/articles/5/approve" -H "Authorization: Bearer <editor_token>"

# 普通用户访问后台 → 403
curl "http://localhost:8080/api/admin/dashboard" -H "Authorization: Bearer <user_token>"
```

### 完成标准
- 审核通过后文章前台可见,驳回后作者能看到原因
- 普通用户访问后台接口返回 403
- 图片上传后文件落在 uploads/ 且数据库有记录

## 建议开发顺序(最小可跑通优先)

```
阶段一(模型) → 阶段二(JWT) → 阶段三(用户) → 阶段四(投稿)
    → 阶段五(前台) → 阶段六(后台) → 阶段七(打磨)
```

这样每完成一个阶段,系统都"多能跑一块",而不是憋到最后一次全做完。
